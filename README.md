# Al’Dente — Cucina italiana

Обновлённая версия системы заказов на Next.js и Supabase.

## Обновление существующего проекта

1. Замените исходники, сохранив свою `.env.local`.
2. Выполните **supabase/migrations/002_atomic_orders.sql**, затем **supabase/migrations/003_roles_and_permissions.sql**, затем **supabase/migrations/004_warehouse.sql**, затем **supabase/migrations/005_archive_and_batch_inventory.sql** в SQL Editor существующего проекта Supabase. Миграция ролей не удаляет заказы или меню. Первый старый `admin` станет `creator`; если админов не было, создателем станет самый ранний зарегистрированный профиль.
3. Выполните `npm ci`, затем `npm run build` и `npm start`. Для разработки: `npm run dev`. Требуется Node.js 20.9 или новее.

## Первый запуск

1. Создайте проект Supabase и скопируйте `.env.example` в `.env.local`. Укажите URL и публичный anon key.
2. По очереди выполните `supabase/migrations/001_schema.sql`, `supabase/migrations/002_atomic_orders.sql`, `supabase/migrations/003_roles_and_permissions.sql`, `supabase/migrations/004_warehouse.sql`, `supabase/migrations/005_archive_and_batch_inventory.sql`, затем `supabase/seed.sql`. Не запускайте seed повторно поверх своего изменённого каталога без проверки его содержимого.
3. В Authentication включите Email provider. Для используемых рабочих логинов (`login@internal.local`) отключите подтверждение email.
4. Выполните `npm ci` и `npm run dev`, откройте http://localhost:3000 и создайте рабочий аккаунт.

## Что изменилось

- Единая мультяшная итальянская стилистика: кремовая бумага, томатный и базиликовый цвета, иконки, анимации, светлая и тёмная темы.
- Плитки с названием сверху и локальной векторной иллюстрацией под ним; поиск, категории, счётчики выбранных порций. Для всех 35 позиций исходного меню подготовлены отдельные SVG-рисунки; они привязаны по точному названию и учитывают тип блюда и начинку. `image_url` сохранён в данных, но фотографии не используются в новом интерфейсе.
- Чек с изменением количества, скидкой, обработкой ошибок и защитой от повторного нажатия во время запроса. После оформления открывается сам чек.
- Работник видит только свои чеки и только личную отчётность. Менеджер и создатель видят чеки всей команды.
- Отчёт с фильтром дат и сотрудников, общей сводкой по команде, персональными показателями, пиццей долей продаж и пастой рейтинга блюд. Имя сотрудника берётся из его профиля регистрации.
- Менеджер и создатель могут архивировать текущий отчётный период: система сохраняет короткую карточку «период — выручка — прибыль», после чего текущие чеки удаляются из активной отчётности одной транзакцией.
- Роли: `worker` — заказы и личная отчётность; `manager` — общая отчётность, все чеки и изменение цен; `creator` — всё перечисленное плюс вкладка «Пользователи» для назначения ролей прямо на сайте. Ограничения продублированы в RLS и серверных API.
- Цены блюд и ингредиентов доступны только менеджеру и создателю. Есть поиск, проверка цены, состояние сохранения и сообщение об ошибке. Изменение ингредиента запускает существующий пересчёт себестоимости. Старые чеки не меняются.
- Оформление заказа атомарно: цены и себестоимость читаются из БД, чек и его позиции записываются одной транзакцией. Если цена изменилась во время выбора, в итоговом чеке применяется актуальная цена БД.
- Вкладка «Склад» доступна всем ролям для просмотра. Менеджер и создатель редактируют остатки и сохраняют все изменённые позиции одной общей кнопкой «СОХРАНИТЬ»; работник видит только значения.
- При выборе блюд рядом с чеком появляется итоговая сводка ингредиентов по всей корзине: сколько требуется и сколько есть на складе. При нехватке оформление блокируется.
- «Куриный бульон» перенесён из категории «Супы» в «Другое».
- При продаже ингредиенты списываются по `dishes.recipe` в той же транзакции, что и чек. Два устаревших ключа рецептов (`Лепешки` и `Повареная соль`) автоматически исправляются миграцией 004.
- Мобильная компоновка, видимый фокус с клавиатуры и отключение анимации при prefers-reduced-motion.

## Проверки

`npm run build` — сборка с проверкой TypeScript. `npm run typecheck` — отдельная проверка типов.

В браузере на тестовом меню проверены добавление и количество порций, расчёт скидки, поиск, категории, сохранение корзины после ошибки сервера, мобильная компоновка и тёмная тема. Снимки `docs/interface-preview.png` и `docs/mobile-preview.png` показывают интерфейс на данных исходного каталога; тестовый маршрут в приложение не включён. `docs/illustrations-preview.png` — все 35 рисунков, `docs/illustrations.md` — соответствие файлов названиям.

Работа с реальным Supabase требует ваших настроек и применения миграции; учётные данные в исходном архиве отсутствуют.

## Файлы

`src/app` — страницы и API; `src/components` — интерфейс; `public/dishes` — отдельные SVG-рисунки; `src/lib/dishIllustrations.json` — привязка названий к изображениям; `src/app/globals.css` — тема и адаптивная вёрстка; `supabase` — схема и каталог.

Исходный импорт Excel сохранён в `scripts/import_excel.py`.

## Обновление визуала и валюты

Все денежные значения отображаются в USD ($), включая меню, чеки, отчёты и редактор цен. Это смена обозначения валюты без конвертации: число 20 становится $20.00. Числа в базе не меняются; исторические чеки также отображаются в USD. При необходимости задайте нужные цены вручную.

Добавлены фон с кухонными рисунками, клетчатые детали, иллюстрированный баннер, подсветка и наклон карточек при наведении, анимации кнопок, вкладок, иконок и графиков. При настройке системы «уменьшение движения» анимации отключаются. Дополнительных SQL-миграций для этого обновления не требуется.
